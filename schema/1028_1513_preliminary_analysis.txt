● GameSpace（後台）與 GamiPort（前台）平台差異完整戰略分析 --- **analyzed by claude code**

  基於多代理對兩個代碼庫的深入探索，以下是您從後台平台轉移到前台平台的完整戰略指南。

  ---
  執行摘要

  GamiPort MiniGame Area 狀態：約完成 5%（僅框架）
  GameSpace MiniGame Area 狀態：完成 100%（生產就緒）

  關鍵發現：GamiPort 的 MiniGame area 本質上是一個空架構，只有 5 個檔案，而 GameSpace 有 300+
  個檔案。這是一個全新實作的機會，您可以選擇性地移植 GameSpace 已驗證的模式。

  第二部分：驗證與授權差異

  2.1 驗證方案

  | 面向        | GameSpace（後台）                     | GamiPort（前台）                    |
  |-----------|-----------------------------------|---------------------------------|
  | Cookie 名稱 | GameSpace.Admin                   | GamiPort.User                   |
  | 方案        | 自訂 AdminCookie                    | 預設 CookieAuthenticationDefaults |
  | 會話長度      | 4 小時                              | 7 天                             |
  | 身份系統      | 雙重：ASP.NET Identity + AdminCookie | 僅 Cookie（無 Identity）            |
  | 用戶模型      | Manager（管理員）vs User（會員）           | 僅 User                          |
  | 登入路徑      | /Login                            | /Login/Login/Login              |

  2.2 Claims 結構

  GameSpace Claims（管理員/經理）：
  new Claim("IsManager", "true"),              // 關鍵管理員標記
  new Claim("mgr:id", managerId),              // 經理 ID
  new Claim("perm:Admin", "true"),             // 權限作為 claims
  new Claim("perm:Pet", "true"),
  new Claim("perm:Shopping", "true"),
  new Claim(ClaimTypes.Role, roleName)         // 基於角色

  GamiPort Claims（用戶）：
  new Claim("AppUserId", userId),              // 主要用戶識別符
  new Claim(ClaimTypes.NameIdentifier, userId), // 標準 claim
  new Claim("UserNickName", nickname),
  new Claim("EmailConfirmed", "true/false")
  // 無權限 claims，無角色 claims，無管理員標記

  2.3 用戶上下文抽象

  GameSpace：IUserContextReader → AuthSnapshot
  // 返回具有管理員/用戶區分的快照
  AuthSnapshot snap = reader.Read(httpContext);
  bool isAdmin = snap.IsManager;
  int? managerId = snap.ManagerId;
  int? userId = snap.UserId;

  // 解析順序：Items → Cookies → Claims（三層回退）

  GamiPort：IAppCurrentUser（支援非同步）
  // 基於屬性，具備非同步 DB 回退
  var me = httpContext.RequestServices.GetRequiredService<IAppCurrentUser>();
  int userId = me.UserId;                    // 快速路徑（僅 claims）
  int userId = await me.GetUserIdAsync();    // 非同步路徑（可能查詢 DB）

  // 解析順序：Items → Claims → DB 映射（非同步）

  戰略意義：GamiPort 在其驗證層中沒有「管理員」vs「用戶」的內建概念。如果您需要在 GamiPort
  中實作管理員功能，需要實作單獨的授權策略。

  第三部分：資料庫與 DbContext 差異

  3.1 DbContext 註冊

  GameSpace（2 個 DbContext）：
  // 1. ApplicationDbContext - ASP.NET Identity（IdentityUser、Roles 等）
  builder.Services.AddDbContext<ApplicationDbContext>(opt =>
      opt.UseSqlServer(identityConn));

  // 2. GameSpacedatabaseContext - 業務邏輯（Users、Pet、Wallet 等）
  builder.Services.AddDbContext<GameSpacedatabaseContext>(opt =>
      opt.UseSqlServer(gameSpaceConn));

  // Identity 整合
  builder.Services.AddDefaultIdentity<IdentityUser>(...)
      .AddEntityFrameworkStores<ApplicationDbContext>();

  GamiPort（1 個 DbContext）：
  // 僅 GameSpacedatabaseContext - 無 Identity
  builder.Services.AddDbContext<GameSpacedatabaseContext>(opt =>
      opt.UseSqlServer(gameSpaceConn));

  // 不使用 Identity 的手動密碼雜湊
  builder.Services.AddScoped<IPasswordHasher<User>, PasswordHasher<User>>();

  戰略意義：兩個平台共享相同的 GameSpacedatabaseContext 並可訪問相同的 20 個表。區別在於 GameSpace 使用 Identity
  進行管理員驗證，而 GamiPort 使用純 cookie 進行用戶驗證。

  4.2 服務架構模式

  GameSpace 模式：類 CQRS 分離
  服務層（三層）：
  ├── 協調器：MiniGameAdminService（門面）
  ├── Query 服務：僅讀取操作，使用 AsNoTracking()
  │   ├── PetQueryService
  │   ├── WalletQueryService
  │   ├── SignInQueryService
  │   └── GameQueryService
  └── Mutation 服務：寫入操作，使用交易
      ├── PetMutationService
      ├── WalletMutationService
      ├── SignInMutationService
      └── GameMutationService

  GamiPort 模式：每功能一服務（更簡單）
  服務層：
  ├── ChatService（處理聊天 DB 操作）
  ├── RelationService（好友管理）
  ├── NotificationStore（記憶體內通知）
  └── 尚無 MiniGame 服務

  戰略建議：對於前台平台，您可能不需要完整的管理協調層。考慮實作更簡單的每功能一服務模式：
  - PetClientService（面向前台的寵物操作）
  - WalletClientService（用戶錢包操作）
  - SignInClientService（用戶簽到）
  - GamePlayClientService（遊戲遊玩操作）

  第六部分：過濾器與中介軟體差異

  6.1 自訂過濾器

  GameSpace（4 個自訂過濾器，位於 Areas/MiniGame/Filters/）：

  | 過濾器                             | 目的                               | 用途                |
  |---------------------------------|----------------------------------|-------------------|
  | MiniGameAdminAuthorizeAttribute | 驗證管理員驗證與 DB 角色檢查                 | 套用於管理控制器          |
  | MiniGameAdminOnlyAttribute      | 輕量級管理員檢查（僅 claims）               | [Authorize] 的替代方案 |
  | MiniGameProblemDetailsFilter    | RFC 7231 Problem Details JSON 錯誤 | 全域例外處理            |
  | IdempotencyFilter               | 防止重複請求（60 秒視窗）                   | 套用於變更端點           |

  GamiPort：無自訂過濾器

  戰略建議：將這些過濾器移植到 GamiPort 並進行修改：

  1. 跳過管理過濾器 - 前台平台不需要
  2. 移植 ProblemDetailsFilter - 對一致的 API 錯誤有用
  3. 移植 IdempotencyFilter - 對防止雙重提交至關重要（例如雙重簽到、雙重優惠券兌換）
  4. 創建新的：RateLimitFilter - 限制每日遊玩次數、每日簽到次數

  範例：寵物前台服務（從 GameSpace 移植）

  從 GameSpace（面向管理員）：
  // GameSpace/Areas/MiniGame/Services/PetService.cs
  public class PetService : IPetService
  {
      public async Task<Pet> GetPetByIdAsync(int petId);
      public async Task<List<Pet>> GetAllPetsAsync();  // 僅管理員
      public async Task UpdatePetAsync(Pet pet);       // 管理員可編輯任何寵物

      public async Task<bool> ChangePetBackgroundAsync(int petId, string bgCode);
  }

  到 GamiPort（面向前台）：
  // GamiPort/Areas/MiniGame/Services/PetClientService.cs
  public class PetClientService : IPetClientService
  {
      private readonly GameSpacedatabaseContext _db;
      private readonly IAppCurrentUser _currentUser;

      // 用戶只能訪問自己的寵物
      public async Task<Pet?> GetMyPetAsync()
      {
          var userId = await _currentUser.GetUserIdAsync();
          return await _db.Pets
              .AsNoTracking()
              .FirstOrDefaultAsync(p => p.UserId == userId && !p.IsDeleted);
      }

      // 用戶對自己寵物的操作
      public async Task<bool> InteractWithPetAsync(string actionType)
      {
          // actionType: "feed", "bathe", "play", "sleep"
          var userId = await _currentUser.GetUserIdAsync();
          var pet = await _db.Pets.FirstOrDefaultAsync(p => p.UserId == userId);

          // 套用互動獎勵（基於 PetInteractionBonusRules）
          switch (actionType)
          {
              case "feed": pet.Hunger = Math.Min(100, pet.Hunger + 20); break;
              case "bathe": pet.Cleanliness = Math.Min(100, pet.Cleanliness + 25); break;
              // ... 等等
          }

          await _db.SaveChangesAsync();
          return true;
      }

      public async Task<bool> ChangeSkinColorAsync(string colorCode, int pointsCost)
      {
          var userId = await _currentUser.GetUserIdAsync();

          // 驗證用戶有足夠點數
          var wallet = await _db.UserWallets.FirstOrDefaultAsync(w => w.UserId == userId);
          if (wallet.UserPoint < pointsCost) return false;

          using var transaction = await _db.Database.BeginTransactionAsync();
          try
          {
              // 扣除點數
              wallet.UserPoint -= pointsCost;

              // 更新寵物
              var pet = await _db.Pets.FirstOrDefaultAsync(p => p.UserId == userId);
              pet.SkinColor = colorCode;
              pet.SkinColorChangedTime = DateTime.UtcNow;
              pet.PointsChanged_SkinColor = pointsCost;

              // 記錄交易
              _db.WalletHistories.Add(new WalletHistory
              {
                  UserId = userId,
                  ChangeType = "SPEND",
                  PointsChanged = -pointsCost,
                  ItemCode = $"SKIN_{colorCode}",
                  Description = "寵物換膚色",
                  ChangeTime = DateTime.UtcNow
              });

              await _db.SaveChangesAsync();
              await transaction.CommitAsync();
              return true;
          }
          catch
          {
              await transaction.RollbackAsync();
              return false;
          }
      }
  }

  總結：關鍵要點

  1. GamiPort MiniGame 基本上是空的 - 您從零開始構建，以 GameSpace 為參考
  2. 不要移植管理功能 - 僅專注於面向前台的功能

  6. 專注於 UX - 前台 UI 應該是遊戲化和行動友善的，而非管理風格表單
  7. 實作冪等性 - 對防止重複簽到/兌換至關重要
  8. 遵循規格 - README_合併版.md 第 3 節定義了確切需要的前台功能

● GameSpace（後台）與 GamiPort（前台）平台差異分析 --- **analyzed by codex**

• 啟動與依賴註冊差異

  - GameSpace 同時註冊 Identity 與業務 DbContext，分別指向 ApplicationDbContext 與 GameSpacedatabaseContext，顯示後台要
    管帳號及營運資料 (GameSpace/Program.cs:45, GameSpace/Program.cs:46)；GamiPort 只保留一個 GameSpacedatabaseContext 供

  - GameSpace 啟用 AddDefaultIdentity 強制信箱驗證，並搭配自訂 Admin Cookie 流程 (GameSpace/Program.cs:51, GameSpace/
    Program.cs:133)；GamiPort 走純 Cookie Authentication + 自家 ClaimFirstLoginIdentity，偏向會員前台登入體驗 (GamiPort/
    Program.cs:55, GamiPort/Program.cs:124)。
  - GameSpace 注入 MiniGame 専用 Service 集合與多層授權/Session/CORS/偽冒防護，強化後台管理控管 (GameSpace/
    Program.cs:71, GameSpace/Program.cs:106, GameSpace/Program.cs:117, GameSpace/Program.cs:192)；GamiPort 則著重聊天、
    通知與即時互動相關服務 (GamiPort/Program.cs:78, GamiPort/Program.cs:84, GamiPort/Program.cs:87)。
  - GameSpace 以 CookieAndAdminCookieLoginIdentity 管理雙 Cookie 驗證邏輯 (GameSpace/Infrastructure/Login/
    CookieAndAdminCookieLoginIdentity.cs:13)；GamiPort 改以 ClaimFirstLoginIdentity 搭配 AppCurrentUser 解析目前會員
    資訊，利於前台情境 (GamiPort/Infrastructure/Login/ClaimFirstLoginIdentity.cs:12, GamiPort/Infrastructure/Security/
    AppCurrentUser.cs:14)。

  資料夾與橫切服務
